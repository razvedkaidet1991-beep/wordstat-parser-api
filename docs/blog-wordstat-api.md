# Как я пробиваю Wordstat без браузера: свой скрипт на Yandex Cloud API

Я технический SEO-специалист. Часть работы — семантика: частоты, уточнённые формы, расширение ядра по «Популярным» в Яндекс Вордстате. Руками это терпимо на сотне фраз. На тысячах — уже нет: копипаст, капчи, отвалившиеся сессии, Selenium, который «вчера работал».

## Что умеет скрипт

Два режима из одного `wordstat_api.py`:

1. **Частоты** — читает `input/queries.txt`, пишет строки в `output/wordstat_report.xlsx`.
2. **Сбор фраз** — топ «Популярные» (до 2000 на seed), минус-слова из `input/stop_words.txt`, результат в `output/wordstat_words.txt`.

Для частот можно выбрать типы мультивыбором:

- `b` — базовая;
- `e` — точная (`"фраза"`);
- `p` — уточнённая (`"!слово !слово"`).

По умолчанию — **только базовая**. Это сознательно: каждый тип = отдельный запрос к API, а квота Wordstat в Search API по умолчанию около **~100 запросов в час**. Три типа на фразу съедают лимит втрое быстрее.

## Прогресс и квота — как я это заложил

Успешно обработанный seed сразу пишется в `output/` и **удаляется** из `input/queries.txt`. Повторный запуск продолжает с оставшихся строк; Excel и файл слов **дописываются**, а не перезаписываются.

При серии **429** (я останавливаю после 10 подряд) прогресс уже сохранён — можно вернуться позже, когда квота отдохнёт. Увеличение лимита Wordstat обычно через поддержку Yandex Cloud; в консоли «Квоты» строка может не отображаться явно.

Между запросами небольшая пауза (~0,25 с), чтобы не упираться ещё и в RPS.

Практический workflow, которым я пользуюсь:

1. Seed-лист → режим **сбора фраз** → большой `wordstat_words.txt`.
2. При необходимости чищу список, кладу его в `queries.txt`.
3. Режим **частот** с `--freq-types b` (или Enter в меню) — максимум фраз на часовую квоту.
4. Точную/уточнённую гоняю точечно по уже отфильтрованному ядру (`be` / `bep`), когда нужны операторы.

## Быстрый старт (без секретов в статье)

Подробная выдача ключа — в репозитории: [docs/API_KEY.md](API_KEY.md). Кратко:

1. В Yandex Cloud завести API-ключ с нужными правами на Search API и знать `folder_id`.
2. Скопировать `data/credentials.example.txt` → `data/credentials.txt`, прописать `api_key` и `folder_id` (файл в `.gitignore`).
3. Поставить зависимости в venv, положить запросы в `input/queries.txt`.
4. Запуск:

```bash
python wordstat_api.py
```

или без меню:

```bash
python wordstat_api.py --mode 1 --freq-types b
python wordstat_api.py --phrases
```

Ключ в публичный репозиторий не пушить. Для рабочего кода мне удобнее **private** GitHub.

## Грязные фразы: кавычки, «Ох!» и 400 Invalid query

В семантике часто встречаются названия в кавычках (`Студия "Ракурс" дорамы`) или восклицательные знаки вроде `Ох!`. Для API Wordstat такие символы в «голом» seed легко дают **HTTP 400 Invalid query**.

Перед запросом скрипт нормализует строку: снимает кавычки разных видов и `!`, плюс ряд служебных символов (`&`, `/`, `|` и т.п.). Операторы точной/уточнённой частоты навешиваются уже отдельно, через форматирование запроса — их не нужно тащить внутри исходной фразы.

Если после нормализации запрос пустой или API всё же вернул 400, seed уходит в `output/invalid_queries.txt` и снимается с очереди — прогон не зависает.

## Кому подойдёт — и когда нет

**Подойдёт**, если вы:

- уже думаете списками и файлами, а не разовыми кликами в интерфейсе;
- готовы один раз настроить Cloud и ключ;
- согласны жить с часовой квотой и планировать батчи.

**Не замена** веб-Вордстату «на глаз»: регионы, ассоциации, вся визуальная аналитика в UI — это другой продукт. Скрипт закрывает узкую задачу: **массово снять totalCount и топ фраз** через API и сохранить результат.
